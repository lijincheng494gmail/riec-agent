# RIEC-Agent v1.1 rule-design scope and version boundary

Status: `DESIGN_DRAFT_NOT_PREFROZEN`

## Purpose

This package defines a candidate governance extension for adaptive, tool-using scientific agents. Its narrow target is the gap exposed by the frozen economy-provider campaign: RIEC-Core v1.0 qualified structural admissibility, but did not itself provide a holdout-equivalent numerical guard against selecting a lucky winner from many structurally admissible routes.

The proposed architecture is therefore a non-compensatory composition:

`RIEC-Core v1.0 structural qualification` + `RIEC-Agent numerical evidence-authority layer`

The extension governs search lineage, claim families, evidence reuse, protected-evidence access, multiplicity, sequential adaptation, final confirmation, and claim authority.

## Immutable boundaries

1. RIEC-Core v1.0 remains frozen and unchanged.
2. The new rules are an external RIEC-Agent layer; they are not represented as historical Core functionality.
3. The completed Codex/Qwen/DeepSeek campaigns remain immutable evidence, including all adverse, null, incomplete and non-replicating outcomes.
4. No threshold in this draft is fitted to the observed provider outcomes.
5. This package authorizes no new model calls, experiments, training, prediction, provider spending, or lockbox access.
6. Old Neuro-A and Neuro-B artifacts are outside scope.
7. This is not a preregistration or implementation freeze. Simulation, power analysis, implementation verification and independent scientific review must precede a future pre-outcome freeze.

## Scientific question

When one or more adaptive agents can execute many data-dependent scientific trajectories, what rules prevent search freedom, repeated validation access, evidence duplication, or claim reformulation from silently increasing the authority of the final claim?

## Critical control principle

Development search volume alone does not invalidate a final test when all of the following hold: exactly one claim family is frozen before access, the route and decision rule are frozen, the final confirmation set is genuinely untouched and independent, it is accessed once, and the test is valid for that claim. In this one-shot case, no additional multiplicity penalty is imposed merely because development search was extensive.

RIEC-Agent v1.1 is necessary only where the one-shot conditions fail or where numerical confirmation alone cannot establish structural claim admissibility.

## Non-goals

- Claiming that any LLM is universally better or worse.
- Making agent consensus count as independent evidence.
- Replacing domain-specific estimands, uncertainty models, or deployment definitions.
- Treating a low p-value as compensation for a failed Core gate.
- Manufacturing scenarios solely to force the hybrid framework to win.
- Claiming that all agentic science is covered by a synthetic benchmark.
