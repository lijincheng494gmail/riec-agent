# RIEC-Agent v1.1 design decision log

## Accepted decisions

### DD-001 — Extension, not Core amendment

The numerical authority layer is versioned as RIEC-Agent v1.1 and composes with unchanged RIEC-Core v1.0. This preserves the Core development boundary and avoids rewriting historical claims.

### DD-002 — Two independent axes

Structural admissibility and numerical confirmation are separate non-compensatory axes. Neither receives a total score and neither can repair failure of the other.

### DD-003 — One-shot holdout is a legitimate strong baseline

One frozen claim tested once on untouched independent evidence remains valid after arbitrary logged development search. The design will not divide alpha by the number of development routes in this case.

### DD-004 — Search accounting follows evidence and claim family

The global ledger is indexed by evidence identity and claim family, not by agent identity. Adding models or sessions increases search capacity but not evidence.

### DD-005 — Final multiplicity follows claims tested on confirmation evidence

The confirmatory error family is the frozen claim batch evaluated on C. Development route count is an audit variable. Repeated protected access receives separate sequential accounting.

### DD-006 — Information access is irreversible

Protected evidence cannot be made untouched again after information release. A new session, renamed file or new agent does not reset state.

### DD-007 — No chain-of-thought requirement

Scientific auditability requires observable actions and evidence feedback, not hidden reasoning. The broker ledger records sufficient causal search history without requesting private chain-of-thought.

### DD-008 — Safety cannot be purchased with universal abstention

Safety and true-claim coverage are co-primary concepts. False blocking, abstention and regret remain visible rather than being hidden in one aggregate score.

### DD-009 — Conventional alpha is a design default, not an outcome-tuned threshold

Familywise alpha 0.05 is retained as a conventional candidate default. Minimum effects, equivalence margins, sequential spending rules, completion thresholds and non-inferiority margins remain unresolved until outcome-blind simulation and review.

### DD-010 — Contaminated confirmation does not erase independent qualification

Static executable-design review resolved one draft wording inconsistency in case CA-009. Contamination permanently blocks T3 from the affected C pool, but a separate, independently valid Q result may still retain T2 authority. Without such Q evidence, the maximum remains T1. This clarification changes no numerical threshold and was made before simulation execution.

## Rejected alternatives

### RJ-001 — Bonferroni over every development route

Rejected because a genuinely untouched one-shot C test validates the selected claim directly; penalizing every D route would be needlessly conservative and would rig the comparison against ordinary holdout validation.

### RJ-002 — Count agents as independent replications

Rejected because agents operating on the same data are search procedures, not evidence units.

### RJ-003 — Add numerical winner risk to an existing Core gate after the fact

Rejected because this would change the frozen meaning of Core v1.0 and retroactively reinterpret the failed campaign.

### RJ-004 — Tune a new cutoff from Qwen/DeepSeek outcomes

Rejected because it would convert the current negative pilot into training data for the claimed solution. Future thresholds require outcome-blind simulation followed by a new freeze.

### RJ-005 — Make holdout-only intentionally weak

Rejected. The protected one-shot comparator must use the same final evidence identity, estimator and legitimate sample size as the hybrid arm.

### RJ-006 — Use one utility score as the primary outcome

Rejected because chosen costs can reverse the ranking of abstention-heavy and permissive policies. Separate error, blocking, coverage and cost outcomes remain primary evidence.

## Unresolved before prefreeze

1. Exact construction and validity proof/test for the qualification e-process or alpha-spending controller.
2. Minimum effect and equivalence margins for each mission family.
3. Protected feedback payload classes and their query debits.
4. Independent mission count, repeated seeds and power.
5. Arm-level completion threshold and missingness estimand.
6. Non-inferiority margin for the R0 one-shot control.
7. Claim-family ontology tests for nested endpoints/subgroups.
8. Provider roster, immutable model identifiers and cost ceilings.
9. Which risk regimes are synthetic, derived, or real-domain demonstrations.
